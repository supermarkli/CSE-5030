# Lab 5 零基础背景笔记

## 1. 这次 lab 到底在做什么

这次 lab 的主线不是“跑几个 benchmark 然后抄表格”，而是让你真正理解：

```text
为什么 Out-of-Order (OOO) 处理器有时比 in-order 快很多，
有时又快不了那么多。
```

这次实验分 3 个部分：

1. `Instruction-Level Parallelism (ILP)`
   看同样都是 7 条指令一轮，为什么有的循环更适合 OOO。
2. `Tomasulo Scheduling`
   看依赖关系不同，OOO 调度器怎么安排发射和执行。
3. `Memory-Level Parallelism (MLP)`
   看内存访问慢的时候，OOO 能不能靠并行访存把等待时间藏起来。

## 2. 先记住最核心的两个对比

### 2.1 什么是 in-order

`in-order processor` 可以理解成：

- 指令基本按程序顺序进入执行
- 前面的关键依赖没解决，后面的很多指令就动不了
- 遇到长延迟，比如 `load` 很慢，容易整条流水线一起等

它像排队打饭：

- 前面的人卡住了
- 后面的人即使本来能先做，也得跟着等

### 2.2 什么是 Out-of-Order (OOO)

`Out-of-Order processor` 的核心思想是：

- 程序提交结果时仍然保持正确顺序
- 但执行时可以把“已经准备好”的后续指令先做
- 只要不破坏数据依赖和程序语义，就尽量并行

它像厨房做菜：

- 红烧肉还没熟
- 但凉菜、汤、米饭可以先做
- 最后按正确顺序上桌

所以 OOO 的价值在于：

1. 挖出 `instruction-level parallelism`
2. 隐藏 `memory latency`

## 3. 什么是 IPC 和 CPI

### 3.1 IPC

`IPC = Instructions Per Cycle`

意思是：

- CPU 平均每个 cycle 完成多少条指令
- 越大通常代表吞吐越高

例如：

- `IPC = 1`：平均 1 个周期完成 1 条
- `IPC = 2`：平均 1 个周期完成 2 条

### 3.2 CPI

`CPI = Cycles Per Instruction`

意思是：

- 平均每条指令要多少个 cycle
- 越小通常越好

### 3.3 IPC 和 CPI 的关系

粗略理解：

```text
IPC 越大，CPI 越小
```

二者近似互为倒数。

实验里：

- `Q1`、`Q2` 更偏向理解 `IPC`
- `Q4`、`Q5` 更偏向看 `CPI` 和 speedup

## 4. 什么是 cycle 和 latency

### 4.1 cycle

`cycle` 就是一个时钟周期。

你可以把它当成 CPU 的“一个节拍”。

### 4.2 latency

`latency` 是某个操作从开始到结果可用要花多少 cycle。

例如题目默认配置里：

- `LAT_INT_ADD = 1`
- `LAT_INT_MUL = 3`
- `LAT_L1_HIT = 1`
- `LAT_L2_HIT = 8`

意思是：

- 整数加法 1 个周期结果就出来
- 乘法要 3 个周期
- L1 命中 load 很快
- L2 命中 load 明显更慢

## 5. 什么是依赖 dependency

依赖是这次 lab 的核心。

### 5.1 数据依赖 data dependency

后一条指令要用前一条的结果。

例如：

```text
add x3, x1, x2
sub x4, x3, x5
```

第二条依赖第一条，因为它要用 `x3`。

### 5.2 为什么依赖会限制 OOO

OOO 不是魔法。

如果某条指令的输入还没准备好，它再聪明也不能乱算。

所以 OOO 能提速的前提是：

- 有足够多“彼此独立”的指令可以先做

如果全是一条接一条串起来的依赖链，OOO 也会被卡住。

## 6. 什么是 critical path

`critical path` 可以理解成：

- 决定这一轮最短执行时间的那条最长依赖链

也就是：

```text
这轮循环最快也得等它走完
```

如果一轮里面有很多指令，但只有其中 4 条是必须串行的，其他能并行，那么真正限制速度的不是总指令数，而是这 4 条组成的关键路径。

这就是 Q2 和 Q3 的本质。

## 7. 什么是 ILP

`Instruction-Level Parallelism (ILP)` 指：

- 一段程序里，有多少条指令可以在时间上重叠执行

不是看总共有多少条指令，而是看：

- 它们之间有没有依赖
- 能不能同时发射
- 能不能交错执行

### 7.1 高 ILP 的直观特征

- 多条独立计算链
- 多个互不依赖的 load
- 一条指令卡住时，别的指令还能上

### 7.2 低 ILP 的直观特征

- 每一步都要等上一步结果
- load 地址依赖上一次计算结果
- 整个循环像一条很长的单链表

## 8. Q1 里的两个 kernel 为什么差很多

### 8.1 kernel_serial

题目给的是 `pointer-chasing` 风格：

```text
sum += aa[sum & (NELEM-1)]
```

关键点：

- 下一次 `load` 的地址，依赖这一次更新后的 `sum`
- 所以你没法提前知道下一次该读哪里

它的依赖链大致是：

```text
sum
 -> and
 -> sll
 -> add(算地址)
 -> ld
 -> add(更新 sum)
 -> 下一轮继续
```

这是一条很长的串行链。

OOO 即使看见后面的指令，也大多没法提前做，因为地址和数据都还没出来。

### 8.2 kernel_parallel

题目里有两个独立累加器：

- `sa += aa[i]`
- `sb += bb[i]`

关键点：

- `aa` 链和 `bb` 链彼此独立
- 两个 `load` 彼此独立
- 两个加法也基本可以并行推进

所以 OOO 可以：

1. 同时挂起多个独立操作
2. 让一部分指令在别的指令等待时先执行
3. 更充分利用 issue width 和执行单元

## 9. issue width 和 functional units 是什么

题目默认 OOO 配置里写了：

- `Issue width: 2 instructions/cycle`
- `INT units: 2`
- `MUL units: 1`
- `LSU units: 2`

### 9.1 issue width

`issue width = 2` 表示：

- 理想情况下，每个 cycle 最多发射 2 条准备好的指令

所以即使程序有无限并行性，也不可能无限快。

### 9.2 INT units

整数执行单元有 2 个，说明：

- 同一时刻最多支持 2 条整数类操作并行执行

### 9.3 LSU

`LSU = Load Store Unit`

有 2 个，说明：

- 最多可让 2 个访存操作并行推进

这对 `Q4`、`Q5` 很关键，因为最后 speedup 的上限往往就会被这种硬件资源卡住。

## 10. 什么是 Tomasulo

`Tomasulo algorithm` 是经典的 OOO 调度思想。

你不用背实现细节，但要理解它想解决什么：

1. 让准备好的指令先执行
2. 用保留站 `Reservation Station (RS)` 等待操作数
3. 用重排序缓冲 `Reorder Buffer (ROB)` 保证最终按程序顺序提交

### 10.1 RS 是什么

`RS` 可以粗略理解成“候车区”：

- 指令先进去排队
- 如果输入操作数还没到，就等
- 一旦数据齐了、执行单元空了，就发出去执行

### 10.2 ROB 是什么

`ROB` 可以理解成“提交队列”：

- 即使执行顺序乱了
- 最终提交结果时仍按原程序顺序来

这样既能利用 OOO，又能保持程序语义正确。

## 11. Q2 里的 bench_diamond 和 bench_chain

这一步主要让你用 Tomasulo 的眼光看依赖图。

### 11.1 bench_diamond

结构是：

```text
      A
     / \
    B   C
     \ /
      D
```

也就是：

- `B` 依赖 `A`
- `C` 也依赖 `A`
- 但 `B` 和 `C` 彼此独立
- 最后 `D` 依赖 `B` 和 `C`

这叫 `parallel fan-out`。

它的优点是：

- 中间两条分支能并行
- 所以关键路径比较短

### 11.2 bench_chain

结构是：

```text
A -> B -> C -> D
```

每一步都要等前一步结果。

它的问题是：

- 几乎没什么可并行的空间
- OOO 调度器也难以施展

所以这一步你要学会的不是抄答案，而是画出依赖图，再算关键路径长度。

## 12. 如何算一轮最少要多少 cycle

方法很简单：

1. 先列出每条指令的 latency
2. 画出谁依赖谁
3. 沿最长依赖链把 latency 加起来

例如：

- `ld` 结果出来要等若干周期
- `mul` 要等 3 周期
- `add` 要等 1 周期

如果某两条分支能并行，就取它们里更慢的那条，而不是相加。

所以：

```text
最短时间 = critical path 的总长度
不是所有指令 latency 的总和
```

## 13. 什么是 MLP

`Memory-Level Parallelism (MLP)` 指：

- CPU 能否同时挂起多个彼此独立的内存访问

这和 ILP 有关，但不完全一样。

### 13.1 ILP 和 MLP 的关系

- `ILP` 更广，讲的是指令层面的并行
- `MLP` 更具体，讲的是内存访问层面的并行

例如：

- 两个独立 `load` 能一起出去等内存
- 这就是 MLP

如果只能一个一个等，那内存一慢，性能就会很差。

## 14. Q3 为什么要改 LAT_L2_HIT

题目让你把 `LAT_L2_HIT` 从：

- `8`
- 改成 `20`
- 再改成 `40`

目的不是折磨你改配置，而是观察：

```text
当内存越来越慢时，
OOO 对 in-order 的优势会不会无限变大？
```

直觉上：

- 内存越慢，OOO 越有机会通过并行 load 来隐藏等待

但这种优势不会无限增长。

因为硬件资源有限。

## 15. 为什么 speedup 不会无限增长

这一步是 Q5 的核心。

假设有两个完全独立的 load：

- in-order 常常得等第一个，再等第二个
- OOO 可以把两个都尽早发出去，同时等

如果每个 load 都很慢，OOO 的确更占优。

但是最终会碰到上限，比如：

- `issue width`
- `LSU` 数量
- `ROB` / `RS` 容量
- 程序本身可提供的独立 load 数量

本题最关键的 ceiling 往往来自：

- 独立内存请求的并行度上限
- 这里题面明确给了 `LSU units: 2`

所以当每轮最多只能并行挂两次独立访存时，继续把内存延迟调得更大，speedup 会逐渐趋于某个稳定值，而不是无限上升。

## 16. L1 / L2 命中是什么意思

### 16.1 cache 是什么

`cache` 是比主存更快的小存储层。

### 16.2 L1 命中

`L1 hit` 表示：

- 数据在一级缓存里
- 非常快

### 16.3 L2 命中

`L2 hit` 表示：

- L1 没有，但 L2 有
- 还是比主存快，但比 L1 慢

这次题目故意设置：

- Q1 的工作集完全在 `L1D`
- Q3 的工作集超过 `L1D` 但能放进 `L2`

所以：

- Q1 更像在看“依赖结构”和“调度”
- Q3 更像在看“访存延迟”和“并行隐藏能力”

## 17. 为什么同样 7 条指令，性能会不同

这正是这次 lab 最想教你的。

因为性能不只由“指令条数”决定，还由这些因素决定：

1. 有没有依赖
2. 关键路径多长
3. 有多少独立指令可并行
4. 有多少执行单元可用
5. load 要等多久
6. 能否并行发起多个 load

所以：

```text
同样 7 条指令/iteration
不代表同样的 IPC 或 CPI
```

## 19. 你写报告时最常用的表达逻辑

建议永远按这个顺序写：

1. 先说明依赖关系
2. 再指出 critical path
3. 再解释哪些操作能并行
4. 最后说明为什么测得的 IPC/CPI 会这样

不要反过来只写：

- “因为 OOO 更快所以更快”

老师要看的是：

```text
结构原因 -> 调度结果 -> 性能结果
```

## 20. 这次 lab 你至少要掌握的词汇表

- `in-order`：顺序执行风格的处理器
- `out-of-order (OOO)`：乱序执行处理器
- `IPC`：每周期完成多少条指令
- `CPI`：每条指令平均花多少周期
- `ILP`：指令级并行
- `MLP`：内存级并行
- `dependency`：依赖
- `critical path`：关键路径
- `issue width`：每周期最多可发射多少条指令
- `latency`：操作延迟
- `L1D`：一级数据缓存
- `L2`：二级缓存
- `RS`：Reservation Station
- `ROB`：Reorder Buffer
- `Tomasulo`：经典乱序调度思想
- `speedup`：加速比

## 21. 现在你最该记住的结论

- OOO 能提速，前提是程序里真的有可挖的并行性
- 真正限制性能的通常不是总指令数，而是 `critical path`
- `kernel_serial` 慢，不是因为指令更多，而是因为依赖链太长
- `kernel_parallel` 快，不是因为指令更少，而是因为独立链更多
- `bench_diamond` 比 `bench_chain` 更适合 OOO，因为中间有并行分支
- 内存变慢时，OOO 可以靠 `MLP` 隐藏一部分延迟，但隐藏能力有硬件上限
- speedup 不会无限增长，最终会收敛到由硬件资源决定的 ceiling
